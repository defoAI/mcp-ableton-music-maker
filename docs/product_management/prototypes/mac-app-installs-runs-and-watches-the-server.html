Design notes for review

The app never runs the server for a client. Claude Desktop, Claude Code and Cursor each spawn ableton-music-maker over stdio themselves. What the app does is make that invisible process visible and installable: it carries the native binary, puts the Remote Script into Live, writes the client config, and tails the server's local activity log. "Run it" in the menu bar means the app spawns its own short-lived server to test the chain, not that it hosts the one Claude talks to.

Decisions taken in this prototype
  • Menu bar app with a window. Status must be glanceable while Live and Claude have the screen; the window is for setup and the log.
  • The chain is the home screen. Three cells, one state each, one fix each. A producer never has to know which half is broken.
  • The app bundles the binary. On a Mac, download, open, Install. Docker stays the hardened path and the Linux/CI path.
  • Tokens are an estimate and say so. The server sees payload sizes, not the model's context. The number is what a call adds.
  • Local data only. The upload tiers are removed from the server (decision 0004); the app lists what is on disk and deletes it, and there is nothing else to show.
  • Activity log on, payloads off. Names, timings and sizes are needed for the app to be useful; MIDI and names are not, so they stay off.
What the server has to grow
  • A local activity stream: one JSON line per call under the state dir, written only when the log is on. Nothing leaves the machine, but it is new data at rest and gets a Privacy section and a test.
  • A heartbeat file per running server (client name, pid, started) so the app can show which client is connected and warn about a second instance.
  • A --check command that runs the handshake and one read and prints the result as JSON, for the Test step and the menu bar.
  • The installer and handshake already exist as library code in the crate; the app links them rather than shelling out.
Questions, answered 2026-09-19
  1. Bundle the native binary? Yes — the app is the Mac install path (decision 0005).
  2. Who signs it? DefoAI UG, as publisher of the fork; Developer ID to be confirmed before packaging.
  3. Tauri 2 or SwiftUI? Tauri 2; the core links the Rust crate directly.
  4. Telemetry? Removed entirely. Local data only, ever.
  5. Activity log on by default? On for names, timings and sizes; payloads off.
  6. Write the Claude Desktop config? Yes, after showing the entry, with a timestamped backup.
  7. Per-day token view? Out of scope; per call and per session.
